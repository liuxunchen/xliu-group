用 OpenFOAM 把 HP/SP 算一遍：从 0D 反应器到喷管 CFD

刘训臣

十月 3, 2026

本文承接上一篇《从氢氧焰到液氢液氧火箭喷管：HP/SP 到底在算什么》。 那里我们用 JANAF 表手算 + Cantera 交叉验证，得到燃烧室 T_c = 3729.8 K、 喉道 116.87 bar / 3398 K、出口（A_e/A_t = 10）2.48 bar / 1729 K / 3792 m/s。

这篇换一条路：同一套工况，用 OpenFOAM 从头算一遍。 目的不是"再算一次"，而是回答一个问题：工程 CFD 工具和教学手算，能不能对上？

一、两条腿：0D 与喷管

HP 和 SP 是两种题型：

题型给定量解出在 OpenFOAM 里对应什么
HP焓 H、压力 p温度 T + 平衡组成0D 定压绝热反应器（chemFoam）
SP熵 s、一串压力 p沿等熵线的 T + 组成喷管 CFD（rhoCentralFoam）

工况与上一篇完全一致：液氢/液氧，O/F = 6.0（质量比），即每 mol O₂ 配 2.6456 mol H₂； p_c = 206.843 bar；推进剂 298.15 K 进入，元素标准态 H = 0。

二、HP：0D 定压绝热（chemFoam）

chemFoam 是 OpenFOAM 的 0D 反应器：一个网格、没有流动，只解刚性化学 ODE + 能量方程。 能量方程是 h[0] = h0 + integratedHeat，绝热时 integratedHeat = 0，焓严格守恒—— 这正是 HP 的定义。

2.1 第一个坑：H₂/O₂ 在 298 K 根本点不着

按论文口径直接建算例：T = 298.15 K、p = 206.843 bar、H₂/O₂ 化学计量比。

结果：温度纹丝不动。 我们用 Cantera 的定压反应器独立验证了一下——10 秒内温度一点没变（图上的 298.15 K 一条直线）。

这不是 bug，是物理：O/F = 6.0 是富燃工况，H₂/O₂ 在室温下本就是亚稳的，真实的火箭燃烧室靠点火器。 0D 反应器没有点火器，所以它忠实地告诉你"点不着"。

2.2 解法：用「等焓点火初态」

关键热力学事实：

绝热定压过程的终态，只取决于 (H, p, 元素组成)，与路径无关。

所以我们可以从一个已经部分反应、但总焓仍为 0 的状态出发。取组成 O₂ : (1−x)、H₂ : (2.6456−2x)、H₂O : 2x（元素守恒），解

$$\sum_i X_i\, h_i(T) = 0$$

得到 x = 0.30 时 T₀ = 1611.66 K（组成 X(O₂)=0.2092、X(H₂)=0.6114、X(H₂O)=0.1793）。 这个温度下点火延迟约 1e-7 s，chemFoam 顺利冲到平衡。

物理含义：这相当于"燃烧室里已经烧掉了 30 % 的推进剂"。因为终态与路径无关， 结果与从 298 K 点火完全等价——而后者在 0D 里做不到。

2.3 第二个坑：janafThermo::limit() 把温度钳在 Thigh

把算例跑起来后，温度爬到 3500.0 K 就再也不动了，Qdot → 0，然后求解器步长下溢崩溃。

查 OpenFOAM 源码 janafThermoI.H：

if (T < Tlow_ || T > Thigh_) {
    WarningInFunction << "attempt to use janafThermo out of temperature range ...";
    return clamp(T, Tlow_, Thigh_);      // ← 硬钳制
}

而 GRI-Mech 3.0 的热力学文件里，多数组分的 Thigh 就是 3500 K（NASA 多项式高温段的拟合上限）。 我们的平衡温度 3729.8 K > 3500 K，于是被一路钳住。

我们试过换四种 ODE 求解器（seulex / SIBS / Rosenbrock23 / EulerImplicit），全部死在 3500.0 K—— 因为问题不在求解器，而在热物性包。

修复：把 constant/thermo 里所有 Thigh < 5000 的组分提到 5000 K。 （热物性数据本身没问题：外推的 Cp 单调，H₂O 在 4200 K 仍是 60.9 J/(mol·K)。）

那 +1.57 K 是哪来的？ 我们把积分容差从 relTol 1e-3 收到 1e-6 重跑， 结果是 3731.4 K，一模一样。所以这 1.57 K 不是积分误差，而是热物性数据本身的细微差别 （例如 GRI 3.0 的 OH 生成焓与 Cantera 用的值差约 360 J/mol）。relTol 1e-3 已经足够。

三、SP：喷管 CFD（rhoCentralFoam）

rhoCentralFoam 是密度基、显式、专门做超声速/激波的求解器（Kurganov 通量）。 我们建的是一段二维平面收缩-扩张喷管：喉道半高 10 mm，出口半高 100 mm（A_e/A_t = 10）， 壁面用 slip（无粘），对应上一篇"绝热、无摩擦、等熵"的假设。

边界：入口给燃烧室总状态等熵反解出来的静压/静温/速度；出口超声速外推。

3.1 第三个坑：Y 场是质量分数，不是摩尔分数

第一次跑，入口边界设的是 87.4 bar，可算出来内部第一个单元只有 49 bar， 出口速度虚高到 5700 m/s（对应的能量足以把气体冷却到负温度——明显不物理）。

排查了很久，最后发现是初场里 5 个组分的 Y 场写成了摩尔分数：

组分摩尔分数 X（错当 Y 用）正确质量分数 Y
H₂O0.66300.89241
H₂0.24970.03761
O₂0.00360.00861
H0.03370.00254
OH0.04630.05883

带进混合物分子量一算就露馅了：错误的 Y 给出 W = 5.08 g/mol，正确的应该是 13.38 g/mol—— 差 2.6 倍，比气体常数、声速、密度全错。

教训：OpenFOAM 里 Y 永远是质量分数，X 才是摩尔分数。 从 JANAF/Cantera 的平衡组成（摩尔分数）搬到 CFD 初场时，必须先乘分子量再归一化。

改成质量分数后，入口内部值立刻变成 87.01 bar，与边界设定 87.40 bar 一致。

3.2 第四个坑：型面尖角会炸

接着做完整喷管（驻室 → 收缩段 → 喉道 → 扩张段）。这次换了新花样：

跑到 2.5e-7 s 就 FPE 崩溃，而且不管怎么调都崩在同一位置。把中间场写出来一看：

时刻p 范围T 范围
t = 0（初场）2.64 ~ 195.2 bar1821 ~ 3694 K
t = 9e-8 s0.27 ~ 207 bar200（被 Tlow 钳住）~ 4238 K
t = 2.2e-7 s0.02 ~ 223 bar200 ~ 4420 K

压力掉到 0.02 bar、温度被钳到 Tlow = 200 K——这是数值奇点。 而极值出现的位置是 x 索引 15~27，正是驻室平直段 → 收缩段的那个凸角。

原因很清楚：型面斜率在那里从 0 突变到 −0.2（dh/dx 不连续）。 初场的一阶导数不连续，显式格式就会在角点附近产生非物理膨胀。

修复：把型面改成余弦过渡，消除所有斜率尖角：

$$h(x)=\begin{cases} H_t+(H_c-H_t)\cdot\tfrac12\left(1+\cos\frac{\pi x}{L_t}\right), & x\le L_t \quad(\text{收缩段})\\[4pt] H_t+(H_e-H_t)\cdot\tfrac12\left(1-\cos\frac{\pi (x-L_t)}{L-L_t}\right), & x>L_t \quad(\text{扩张段}) \end{cases}$$

这样在入口、喉道、出口三处 dh/dx 都是 0。改完一次就通了。

顺带一提：余弦型面的喉道（A/A* = 1）给出 116.89 bar / 3395.8 K， 与上一篇严格解的 116.87 bar / 3398 K 几乎重合。

3.2b 第五个坑：多块网格"坐标相同"≠“顶点共享”

型面修好之后，完整喷管能跑完 2 ms 了，但结果仍然不对——入口和出口各一层单元（各 24 格） 从 t = 0.2 ms 起线性漂移：入口升到 5134 bar、出口降到 −12982 bar，温度撞到热力学上限。 内部流场却完全正常（喉道 115.7 bar / 3378 K 已对上）。换入口边界条件（固定速度 / 外推速度） 只改变出问题的子域编号，不解决问题。

追查 blockMesh 的日志，看到一句被忽略的警告：

Found 278 undefined faces in mesh; adding to default patch defaultFaces

再看 checkMesh：

Mesh has 1 solution (non-empty) directions (0 1 0)     ← 只有 y 方向是"非空"的！

根因：我的 140 个块，每个块各写了一套"坐标完全相同、但索引不同"的 8 个顶点。 blockMesh 不会合并这种重复坐标的顶点，于是 139 个块间界面全部落进 defaultFaces （默认类型是 empty），网格在 x 方向被"断开"，退化成 1D。

对比官方 damBreak 教程的多块写法才明白：相邻块必须引用同一批顶点索引。

$$v(i,j,k) = i\,(N_y+1)\cdot 2 + j\cdot 2 + k$$

改完之后：

nInternalFaces: 6556                    （修复前 3220）
undefined boundary faces : 0            （修复前 278）
Mesh has 2 solution (non-empty) directions (1 1 0)
Mesh OK.

教训：多块网格里"坐标相同"不等于"顶点共享"。别用重复坐标糊，要用共享索引。 诊断口诀：看 nInternalFaces 够不够、看 checkMesh 报几个非空方向。

3.3 SP 结果

第一步：纯超声速扩张段（A/A* = 1.05 → 10，从假定的喉道下游起算）。 这一步用来把"变比热 + 质量分数 Y"这套口径先跑通：

位置OpenFOAM上一篇（blog 冻结流）偏差
入口（A/A*=1.05）87.01 bar / 3235 K / 1930 m/s87.40 / 3237 / 1925（设定）≤0.4 %
出口（A_e/A_t=10）p_e2.6595 bar2.4822 bar+7.1 %
出口 T_e1760.5 K1729 K+1.8 %
出口 u_e3751.2 m/s3792 m/s−1.1 %

第二步：完整喷管（驻室 → 收缩段 → 喉道 → 扩张段，余弦平滑型面，A_e/A_t = 10）。 让喉道自己形成（不是假定），这一步才是和上一篇 SP 完全同口径的对比：

位置OpenFOAM上一篇（blog 冻结流）偏差
喉道（M=1）p_t117.016 bar116.87 bar+0.12 %
喉道 T_t3399.4 K3398 K+0.04 %
出口 p_e2.555 bar2.4822 bar+2.94 %
出口 T_e1736.7 K1729 K+0.45 %
出口 u_e3783.3 m/s3792 m/s−0.23 %

声速点自检：喉道处算出 $u_t = 1584.2$ m/s，而当地声速 $a_t=\sqrt{\gamma R T_t}=1590$ m/s，$u_t/a_t = 0.996$——喉道确实是 $M=1$。

读表要点：

  • 完整喷管比"只算扩张段"明显更准（温度差从 1.8 % 收到 0.45 %、压力从 7.1 % 收到 2.9 %、 速度从 1.1 % 收到 0.23 %）。原因很清楚：完整算例里喉道位置是解出来的， 而不是像扩张段算例那样从"假定喉道"等熵反解一个超声速入口状态。
  • 剩下的百分之几来自 140×24 粗网格的数值耗散；做设计用之前应补网格无关性研究。
  • 入口第一格（x≈2 mm）压力偏高约 28 %，是入口边界与内部解的匹配问题（无粘 + 固定入口三量）， 从第二格起即正常（195.34 bar vs 设定 195.17 bar，差 0.09 %）。不影响喉道与出口结论。

图：完整喷管（余弦平滑型面，A_e/A_t = 10）的定常解，t = 2e-3 s。 马赫数：驻室 0.31 → 喉道 1.00（声速点，图上刚过渡到黄绿） → 出口 3.27； 温度：3696 K → 喉道 3399 K → 出口 1737 K； 压力：195 bar → 117 bar → 2.56 bar——全程 76 倍的等熵膨胀。 云图沿轴向的细条纹是 140×24 结构化网格的单元着色痕迹，不是物理波动。

踩坑备注（给后来者）：本机 ParaView 在无头环境下默认 GLX 后端会报 X_GLXCreateContext 失败；加上 --opengl-window-backend OSMesa（配合系统 libOSMesa） 即可纯软件渲染。另外 ParaView 6.0 把色标标签属性从 ColorTransferFunction 挪到了 ScalarBar 上，而且这个构建下色标刻度文字渲染不出来，所以标题与量程标注是用 matplotlib 叠上去的（compose_pv.py）——云图本身完全来自 ParaView。

3.5 一个反直觉的发现：变比热反而"更该用"，但要配对

我们一开始用常比热等效气体（γ = 1.1967、W = 13.384 g/mol，与上一篇手算同口径）跑， 出口是 2.7903 bar / 1844.5 K / 3756.8 m/s。换成真实变比热（GRI-Mech 3.0 的 janaf 数据， 5 组分冻结）后变成 2.6595 bar / 1760.5 K / 3751.2 m/s——温度和压力都明显向参考值靠拢 （T 从 +6.7 % 收到 +1.8 %，p 从 +12.4 % 收到 +7.1 %）。

所以 §3.1 那个 Y 场的坑，卡住的不只是"能不能跑"，而是整个变比热口径。

四、五个坑的清单

#坑症状修复
1H₂/O₂ 在 298 K 不自燃0D 反应器温度纹丝不动（实测 10 s 无变化）用等焓点火初态（终态只取决于 H、p、元素组成）
2janafThermo::limit() 钳制 T ≤ Thigh温度死在 3500.0 K，换求解器无效constant/thermo 的 Thigh 提到 5000 K
3Y 场误用摩尔分数入口 87 bar 而内部 49 bar；出口 u 虚高到 5.7 km/sY 必须是质量分数（先乘分子量再归一化）
4型面斜率尖角角点处 p 跌到 0.02 bar、T 被钳到 200 K → FPE型面改余弦平滑（消除 dh/dx 突变）
5多块网格顶点不共享入口/出口各一层单元线性漂移到 ±10⁴ bar；checkMesh 报只有 1 个非空方向相邻块共享顶点索引（不用重复坐标）；看 nInternalFaces 与 defaultFaces 自检

五、教学手算 vs 工程 CFD：谁验证谁

燃烧室 T_c3756 K3729.8 K3731.4 K
喉道 p_t116.9 bar116.87 bar117.02 bar（完整喷管 CFD）

三套完全独立的方法（查表手算 / 平衡求解器 / 动力学 + CFD）落在同一个答案上， 差在 0.05 %~0.5 % 量级。这说明：

  1. 上一篇的教学结论是可靠的——HP/SP 的核心确实是"焓守恒 + 化学平衡 + 等熵"这三条， 与用什么工具无关；
  2. CFD 不是"更高级的手算"——它解的是动力学 + 守恒律，所以它能告诉你手算告诉不了的事 （比如"298 K 点不着"）；同时它也引入了自己的误差（数值耗散、网格、边界）；
  3. 反过来，手算适合给 CFD 当"体检表"：算例跑出来先看入口能不能对上边界、出口速度对不对， 对不上就说明设置有问题——这次五个坑全是靠这种对照抓出来的。 最典型的是第 5 个：内部场明明"看起来对"，是"入口 87 bar 而内部 49 bar"这种边界对照 把问题逼出来的。

七、小结

  1. HP：OpenFOAM 的 0D 反应器给出 T_c = 3731.4 K，与 Cantera 全平衡差 0.042 %，组成逐项吻合。 容差从 1e-3 收到 1e-6 结果一字不差，说明这 1.5 K 的差来自热物性数据本身、不是积分误差。
  2. SP：完整喷管 CFD 给出喉道 117.02 bar / 3399.4 K（对 blog 差 0.12 % / 0.04 %）、 出口 3783.3 m/s（差 −0.23 %）、出口温度 1736.7 K（差 0.45 %）、 出口压力 2.555 bar（差 2.9 %）。喉道处 $u_t/a_t = 0.996$，声速点自检通过。
  3. 五个坑都很典型：不自燃、温度钳制、Y/X 混淆、型面尖角、多块顶点不共享。 前两个是物理与数据问题，后三个是建模问题——但症状都表现为"求解器崩了"或"结果离谱"， 所以别急着换求解器，先看物理量对不对（“入口能否对上边界"是最快的一把尺子）。
  4. 下一步：① 喷管网格无关性研究（把剩下那百分之几的耗散误差压下去）； ② 用变比热解迭代初场；③ 把算例接到 360 高压燃烧实验平台的设计计算里 （子课题 D：型面坐标输出 → 面积比迭代 → C_F / I_sp 预估，与 CEA 互校）。
