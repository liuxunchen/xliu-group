从实验记录到组会汇报：我们课题组的 AI 协作工作流

从实验记录到组会汇报：我们课题组的 AI 协作工作流

刘训臣2026-11-26

这是一篇写给新同学看的经验帖：我们实验室怎么用「服务器上的 AI 助手 + 内网看板」，把日常实验记录、提交、组会汇报串成一条线。文中截图来自组内看板（内网只读页面，2026-11-26 的快照），示意图由我们绘制。

一、先解决三个问题

刚进组的时候，记录是散的：实验日志在某台电脑的某个文件夹里，图在另一个地方，组会前一天才开始回想这周到底做了什么；笔记本、台式机、服务器各存一份，谁也说不清哪份是最新。

后来我们定了很朴素的三条规矩：

  1. 两个唯一真相：文字记录只写进项目文档（服务器上的 Markdown 文件）；图、论文、代码等文件只存项目文件夹；原始大数据进实验数据区（统一目录，处理过程与原始数据同放）。
  2. 每天只做一件手写的事：把当天做的实验、仿真或数据处理，记成一条子课题步骤。
  3. AI 助手在服务器上运行，不在你自己的电脑上：你只要一条隧道加一个浏览器（或内网网页），记录、整理、生成汇报、提交都在服务器上完成；本机只做必须用图形界面的事——画图、采集数据、建模。

听上去约束不少，但换来的是：所有东西可追溯、组会不用现攒、换了会话 AI 也能接上。

二、一周怎么跑

每天开工：问一句"今天做什么"。 助手会带你过一遍"开工六看"：身份与端口信息、本周组会记录里的任务表（你这行）、@你的待办、你项目文档里的本周步骤、组内博客最新更新、内网看板的每日体检。确认今天的优先级，就可以开工了。

做完就记：一条步骤。 这是全程唯一要手写的东西。比如"今天在平面火焰台上做了三个工况的点火实验，测到点火延迟随当量比的变化，图已存项目文件夹，原始数据在实验数据区"。写清目的、方法、结果和产物——文字进项目文档，图进项目文件夹，原始数据进实验数据区并登记。当天事当天记，不攒到周五。

周三：口头讲进展。 说一句"本周进展"，助手从本周步骤自动汇总要点，你在组会上直接讲——要点只从步骤来。步骤没写，汇报就没有内容，这反过来逼着大家平时就记。

周五 9:00 前：准备组会。 顺序固定三步：先体检本周步骤（有没有漏记、上周计划是否都有对应步骤）→ 由步骤自动生成四段论（已完成 / 未完成+原因 / 下周计划 / 安全核可表）→ 把本周改动冻结成一个提交件上传。四段论不手写——手写的四段论如果指不回具体步骤，会被退回。

组会后：合并与验收。 导师按时间链逐件看、逐件合并，合并结果回写到项目文档；下周一组会逐项验收，验收不通过就退回。下周计划直接从"没闭环的任务"里取，不需要凭空想。

三、提交件长什么样

我们的提交件叫增量件：每次提交冻结一个新文件，文件名带时间戳和类型标识（平时记步骤的"工作件"、周五汇报用的"周五件"），不覆盖自己上一次，也不覆盖别人。每件只写本次改动，件内必须自带两样东西：

  • 「原→改」对照：这一处原来是什么、改成什么，方便导师核对；
  • 「改后新片段」：可以直接粘贴的完整片段，粒度至少到一条完整步骤（或整节、整篇替换块）。

再加三件配套：① 文档增量件本身；② 涉及的图已上传到项目文件夹、并在文中用图片语法引用；③ 本周实验数据已提交到实验数据区。件头写清提交人、时间戳和基线（相对哪一版项目文档）。

不合格会被退回：文件名加上"退回 + 原因"标记，内网看板上一眼能看到。退回原因就七类：缺合规声明、四段论缺段、无步骤编号、步骤引用无效、缺改动对照、声明不一致、安全核可表的设备清单模糊。重交件必须完整自足，旧件即时归档。

四、内网看板：把"组会前才知道"变成"每天可见"

我们有一个内网只读看板，每天自动刷新。它不存第二份真相，只是把服务器上的唯一真相汇总成视图：

  • 每日体检：按"今天是一周里的哪一天"切标准——日程体检看实验场次有没有撞上上课时间；核可表冲突看跨项目是否在同一时段共用设备、场地、人员。自己项目被点名，当天先核对。
  • 本周日程 + 项目文档总览：一张表看全周实验场次；每份项目文档的负责人、参与人和本周进度体检（步骤是否更新、周五件是否已交）一眼可见。
  • 组会记录页：每周一份档案，过程记录、任务表、待办、周总结都在里面，按周归档、一页直达。
  • 文档总览页：规则、模板、技能索引一页列出，找格式、找流程不用翻文件夹。

还有学生提交件页和学生草稿页：前者是导师审阅入口，也是学生自己查"有没有带退回标记的件"的地方；后者汇总每人最新的博客与主页草稿。

五、这些功能是怎么搭起来的（幕后版）

前四节讲的是"怎么用"，这一节讲"背后是什么"。说实话，我们自己也是用了一阵才搞明白：我们看到的只是一个对话窗口，真正干活的是服务器上的助手 + 两本手册 + 两份文件真相 + 一条自动渲染看板的流水线。

一台服务器，每人一个助手。 我们用的助手是一个智能体运行时（DeepSeek Harness，简称 DSH）——它给大模型装上"读文件、写文件、跑命令"的手脚，再加一个网页界面。整个组共用一台内网服务器，每人一个独立实例：自己的账号、自己的对话历史、自己的密钥，互不可见。助手服务只监听服务器本机，网页上不设密码；我们每人用自己的服务器账户连一条加密隧道，把它映射到本机浏览器——本机零安装，换电脑只要重新敲一行命令，软件、密钥、会话历史都在服务器上你自己的账户里。每个实例都是一个常驻服务：开机自动拉起、崩了自动重启，升级和维护由导师那边统一做，我们只管用。

权限写在服务器账户上。 谁能读什么、改什么，由服务器账户权限定死：项目文档区全员可读、学生只读；学生只能写自己的提交区、自己的项目文件夹和数据区。所以"提交走对话"不只是纪律——你直接在服务器上改项目文档，技术上就改不了，这正好和"提交件只含改动"的设计咬合在一起。

两份文件真相。 助手的大脑是模型，但它的记忆全在服务器文件里：文字真相是每个项目一份的 Markdown 项目文档（项目概况、每周记录、子课题步骤……），图、论文、代码进项目文件夹，原始数据进实验数据区。模型本身不"记得"你上周干了什么——这正是"换一个会话、换一个助手也能接上"的原因：上下文不在模型脑子里，在文件里。数据太大不想搬的，也可以留本机——助手经同一条隧道反向读你硬盘、用本机 CPU 算，只把结果收回服务器。

两本手册。 光有模型和文件还不够，还得规定"怎么读、怎么写、按什么格式"。服务器上有两本手册，每次对话自动加载：规则手册——工作纪律、文档模板、口令表，全组读同一份，所以每个助手的行为一致；技能手册——每个标准动作一份分步说明，“开工六看"“记一条子课题"“准备组会"“上传数据"“发博客"都是技能。助手不是凭感觉干，是按手册一步一步做。

大模型具体在干什么。 模型只会两件事：听懂你的话、调用工具（读文件、写文件、跑命令、查网页）。这些功能的前提是同一个：每一步都先留痕成文本——存在项目文档里，按项目、周、步骤编号随时可查。具体来说，都是"读文件 → 按手册处理 → 写文件"的组合：

  • “今天做什么”：按"开工六看"技能，读本周组会记录（任务表里你的行、@你的待办）、你的项目文档（本周步骤）、看板上的每日体检——再按固定模板汇总给你。回答不是模型想出来的，是从文件里查出来的，所以每条都能指回原文。
  • “记一条子课题”：把你口述的内容按模板整理成一条步骤，写进提交区的工作件，并渲染成网页让你当场预览。
  • 四段论：把本周所有步骤读出来，按"已完成 / 未完成+原因 / 下周计划 / 安全核可表"的规则逐条归类，每条标注对应步骤编号。四段论永远指得回步骤——它是从步骤汇总出来的视图，不是模型编的总结。
  • 提交件：先读服务器上最新版的项目文档，把你本周的改动冻结成一个带时间戳的新文件，件内自动生成"原→改"对照和可以直接粘贴的改后片段。导师在合并窗口逐件审核、合并回项目文档。
  • 看板：不是模型实时画的，而是服务器上的定时任务每隔几分钟把项目文档渲染成网页（每日体检、本周日程、文档总表、提交区状态），每天凌晨自动巡检提交区。模型只是这条流水线里"写文件"的一环，看板永远反映文件的真实状态。

为什么这样设计。 一句话：把"判断"留给模型，把"记忆"和"流程"留在文件与手册里。 模型会换、偶尔会错、上下文会丢；只要文件在、规则在、技能在，任何一个助手都能接着干。我们学生要做的，就是把该记的记进文件——剩下的交给这套组合。

六、踩过的坑（都真踩过）

  1. 只传不报 = 没上传。 用 rsync 把文件丢上服务器，却没在对话里说、没登记、没随提交件提交——导师看不到、AI 不知道，等于没做。
  2. 图只写文件名 = 看不到。 文档里只写"图 1、图 2"而没用图片语法引用原图，看板渲染出来是没有图的，直接判违规退回。
  3. 四段论手写 = 退回。 手写四段论容易编，条目也指不回步骤；正确做法是记好步骤，让助手生成。
  4. 提交件不带改动对照 = 退回。 只给结论、不给「原→改」和改后片段，导师没法核，退回重交。
  5. 基线过期 = 整篇对不上。 改文档必须从服务器最新版出发；拿旧副本改出来的差异整篇都错，只能重做。
  6. 文件权限不对 = 导师读不到 = 没提交。 写完立刻自查权限（应为全组可读、组为 students），不对当场修；现在系统每 5 分钟自动兜底一次，但不能依赖它。
  7. 组会前几分钟才交。 周五件至少提前 3 小时（9:00 前）提交，否则组会没法看、合并窗口也来不及。
  8. 一次改一大片。 一条任务只做一件事；一次提交只含当次改动。大改用整节替换块，不要写"半截改动”。

七、这套做法带来了什么

  • 组会不再现攒：四段论从平时的步骤自动生成，周五只是"确认 + 提交”。
  • 可追溯：每条结论都能回到某条步骤、某次提交、某个时间点；导师的每条指导都有编号、状态和验收记录。
  • AI 接得续：换一个会话、换一个助手，读一遍项目文档和组会记录就能接上，不需要你重新讲一遍背景。
  • 数据不丢：文字、图、原始数据各有唯一去处，临时文件不进同步盘。
  • 新人上手快：规则一页读完（工作规则 + 连接卡），每周固定动作照做即可。

八、给新同学的三句话

  1. 当天事当天记：一条步骤就行，别攒到周五。
  2. 提交走对话、一次一版：提交件只含改动、带对照，文件名带时间戳。
  3. 先看看板，再动手：任务在哪、这周排了什么、自己有没有要退回的件，看板上都有。
